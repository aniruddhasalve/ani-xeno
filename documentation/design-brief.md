# Ani Uni design brief

## Product goal

Create a serious interface font that can move between phone UI, tablet layouts, websites, desktop applications, and data-heavy screens without losing its identity or becoming difficult to read.

## Distinct design proposition

Ani Uni will use a controlled responsive system instead of a single frozen cut. Width, optical size, and grade should let product teams solve density and contrast problems while keeping the same family. The goal is practical universality: one recognizable family, multiple context-aware settings.

## Non-negotiable glyph tests

The first proofing set must include `I l 1`, `O 0`, `S 5`, `B 8`, `C G`, `a e`, `r n`, and `m w`. These pairs expose ambiguity and spacing problems early. The UI set must also include arrows, check marks, notification punctuation, slashes, brackets, currency symbols, and numerals with tabular and proportional behavior.

## Platform targets

The first specimen should test a 12–14 px mobile label, a 16 px app body, a tablet navigation label, a responsive website paragraph, and a dense table. Every specimen must record viewport size, font settings, and evidence screenshot.

## What we will not claim yet

Ani Uni is not automatically multilingual because it has a universal name. Devanagari and other scripts require their own design work, language testing, and shaping validation. The first release will state its exact coverage.
